## 3. 實際完成

### 3.1 回放器 `modules/monitoring/server/replay.py`

- **`ScenarioReplay`**：依時間產生 `reading` / `event` / `stats` 訊息。
  - **條件**：同資料包，可匯出才能回放。
  - **讀值**：先取 `(id, timestamp)` 索引，再以 id 分頁取。每頁一個短查詢，可在 `to_thread` 的不同執行緒呼叫，不必共用 cursor。
  - **事件**：以 `is_observable_event` 過濾。
  - **10 分鐘統計**：與匯出器共用 `StatsBuilder`，新增 `close_before` / `close_all`。窗結束時送，最後的殘缺窗在資料結束時送。
  - **順序**：同一時刻依統計 → 事件 → 讀值。
- **`scenario_pack` 重構**：
  - `json_values` / `stats_message`：型別同 Parquet。REAL32 取 float32 的最短十進位表示，讀回逐位元相同。
  - 幾個私有函式改成公開名稱給回放器用。
- **`ReplayClock`**：模擬時間＝起點 + 實際經過秒數 × 速度。
- **預測**：
  - `validate_prediction`：機組、類別、詞彙、手冊引用、文字長度。
  - `prediction_record`：`ts` / `pack_id` 由伺服器填。
- **共用函式**（REST 與 CLI）：`create_run`、`run_view`（狀態）、`predictions_jsonl`。

### 3.2 端點 `server/routers/replay.py`

- **REST（主管）**：
  - 建回放（token 只回一次，DB 只存 sha256）。
  - 列表與狀態：ready / not_started / running / finished / expired / revoked。
  - 撤銷。
  - 下載 `predictions.jsonl`。
- **WS `/ws/replay`**：
  - token 放 `Authorization: Bearer` 或 `?token=`。
  - 單次回放在第一次連線時原子地寫入 `started_at`。
  - 送訊息與收預測是兩個 task，送訊息有鎖。
  - 拒絕時先送 `error` 再以 4401 / 4403 / 4404 / 4409 / 4410 關閉。
  - 播完送 `finished`，再開 10 秒讓途中的預測拿到 ack。
- **實作中改的一點**：原本播完後還有 30 秒「寬限期」收預測。寫合約時發現評分本來就把情境結束後的預測算成對不到 case（誤報），寬限期等於陷阱。改為：模擬時間超過 `sim_end` 後收到的預測一律退回；之後的 10 秒只讓 ack 送達。

### 3.4 code review（code-reviewer：Needs revision → 全修）

審查者對真的 uvicorn 伺服器寫了實測腳本。

**Must-fix**：
- **M1 詞彙檢查在 Docker 裡失效**：
  - 原因：詞彙檔在 `examples/`，Dockerfile 只複製 `run.py` / `modules/` / `shared/`；找不到時原本直接略過。
  - 修法：唯一來源移到 `shared/data/rag_assistant_vocabulary.json`，找不到就匯入失敗。kit 的 `vocabulary.json` 是副本，`build_rag_starter_kit` 同步、測試比對。
- **M2 單次回放的連線上限有競態**：
  - 原因：檢查與 +1 之間有 `await start_replay_run`。實測同時 16 條、上限 4，收進 9 條。
  - 修法：檢查與佔位之間沒有 await；佔位後的任何失敗都還回名額；鍵改為 (DB 路徑, run id)。

**Should-fix**：
- **S1 極端數值讓連線以 1011 斷線**：
  - 原因：超過 4300 位數的整數讓 `json.loads` 丟 `ValueError`；巨大整數的 `confidence` 讓 `isfinite` 丟 `OverflowError`。
  - 修法：每則訊息的處理包一層，失敗只回 `error`；`confidence` 改用比較；`component` 加長度上限。
- **S2 撤銷 / 到期不影響已開的連線**：串流與收尾等待中每 5 秒重讀，撤銷或到期就以 4403 關閉。
- **S3 同情境的練習回放可以先偷看**：
  - 建回放時預設拒絕兩種模式並存（REST 409、CLI exit 1），`allow_overlap` 才放行。
  - 新增 `?check=true`：只回報狀態、不開始計時、不佔名額、不透露出題者備註。
- **S4 每條連線都重載整個情境**：
  - 索引改為 `array('q')` 的 id（id 順序已是時間順序時不排序），依（DB、情境、建立時間、筆數）快取。
  - 4409 / 4410 在載入情境前先擋（4410 只用 MIN / MAX 時間）。
  - 讀值上限 200 萬筆。
- **S5 測試沒守住傳送端的時間因果**：用假時鐘（`wall_time` 與 `asyncio.sleep`）驅動 `_ReplayConnection.stream()`，逐則確認送出時 `due ≤ 現在`；另補下方「補測」的各項。
- **S6 預測與訊息的保護**：每則 64 → 16 KB；每個回放的預測總量 20 MB；uvicorn `ws_max_size` 1 MiB。
- **S7 串流落後時鐘**：
  - 預取下一頁（剩 300 則就先抓）。
  - `json_values` / `scada_values` 去掉逐值的 numpy 索引，約 2 倍快（約 3,800 筆讀值 / 秒）。
  - 正式評測限制「機組數 × 速度 ÷ 取樣週期 ≤ 1000 筆 / 秒」（超過 422）。
  - 實測 600× 落後中位數 0.03 s（原本每頁邊界 0.15 s）；10000× 仍跟不上，只給練習用。
